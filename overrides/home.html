From security alert to reviewed pull request.

Patchy gathers related alerts into Kubernetes Finding resources, adds ownership context, and has a sandboxed coding agent investigate each one. Confident fixes become pull requests; everything else goes to a person. People merge every change.

How patchy stays safe

Related alerts gather

Alerts of one advisory family fold into a single finding for an hour, so one weakness becomes one tracking issue instead of forty.

Context before code

Ownership and infrastructure context arrive on the finding before the investigation decides where it goes.

The agent holds no credential

Agent pods carry no forge or model credential at all. The repository arrives as a digest-verified tarball, and the egress broker adds the model credential on the way out.

People merge every fix

Patchy opens the pull request. People review it and merge it, and can approve, retry or hand off any finding along the way.

Install

Two Helm charts: the stack, then the configuration that switches it on. Getting started walks through the GitHub App and the Secrets first.

The stack

CRDs, controllers, the egress broker and the status page.

helm install patchy \
  oci://ghcr.io/bitwise-media-group/patchy/charts/patchy \
  --namespace patchy --create-namespace

The configuration

Your Integrations and Forges, once the CRDs exist.

helm install patchy-config \
  oci://ghcr.io/bitwise-media-group/patchy/charts/patchy-config \
  --namespace patchy -f values.yaml
